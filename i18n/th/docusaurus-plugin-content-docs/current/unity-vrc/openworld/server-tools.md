# เครื่องมือฝั่งเซิร์ฟเวอร์

แพ็กเกจมี source ภาษา Rust ของโปรแกรมเสริมสองตัว ใช้ OpenWorld ได้โดยไม่ต้องมีทั้งคู่

| โปรแกรม | โฟลเดอร์ | รันที่ | หน้าที่ |
|---|---|---|---|
| `openworld-host` | `Server~` | เซิร์ฟเวอร์ของคุณ | ให้บริการข้อมูล stream รับ deploy และรับข้อความจากโลก |
| `openworld-link` | `Link~` | PC Windows ของผู้เล่น | ส่งต่อข้อความจาก log ของ VRChat ไปยังเซิร์ฟเวอร์ |

build ด้วย `cargo build --release` ในโฟลเดอร์ของแต่ละตัว

## openworld-host

```bash
openworld-host --dir site --port 8080 --token-file token.txt
```

| อาร์กิวเมนต์ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--dir` | `site` | โฟลเดอร์ไฟล์ที่ให้บริการ |
| `--bind` | `0.0.0.0` | ที่อยู่ที่รอรับการเชื่อมต่อ |
| `--port` | `8080` | พอร์ต |
| `--token-file` | ไม่มี | token สำหรับ deploy ใช้ตัวแปรสภาพแวดล้อม `OPENWORLD_TOKEN` แทนได้ |
| `--keys` | `keys` | โฟลเดอร์ key ของข้อความแยกตามโลก |
| `--data` | `data` | โฟลเดอร์เก็บข้อความ |

| เส้นทาง | ทำอะไร |
|---|---|
| `GET /<world>/<file>` | ส่ง `site/<world>/<file>` ถ้ามีโลกเดียวใช้ `GET /<file>` ได้ |
| `PUT /_deploy/<world>` | แตกไฟล์ zip จาก **Package for Host** |
| `POST /ipc` | รับข้อความจาก `openworld-link` |

ถ้าไม่มี token จะ deploy ไม่ได้ และ token ต้องยาวอย่างน้อย 16 ตัวอักษร การ deploy เขียนไฟล์ข้อมูลก่อนแล้วเขียน manifest ท้ายสุด ผู้เล่นจึงไม่เจอ manifest ที่ชี้ไปยังไฟล์ที่ยังไม่มี และไม่ลบไฟล์เลย เพราะโลกที่อัปโหลดไว้ก่อนอาจยังเรียกไฟล์เก่าอยู่ ขนาด zip จำกัดที่ 512 MB หรือ 2 GB เมื่อแตกแล้ว

```bash
curl -X PUT -H "Authorization: Bearer $(cat token.txt)" \
  --data-binary @Stream_xxx.zip https://cdn.example.com/_deploy/myworld
```

:::warning HTTPS และ trusted URL
เซิร์ฟเวอร์ไม่มี TLS ให้วางไว้หลัง Caddy, nginx หรือ Cloudflare Tunnel โดเมนของคุณไม่อยู่ในรายการ trusted URL ของ VRChat ผู้เล่นจึงต้องเปิด **Allow Untrusted URLs** และ VRChat ไม่ตาม redirect
:::

## ส่งข้อความออกจาก VRChat

:::note
ลองดู VRChat Persistence ก่อน การเซฟรายผู้เล่นไม่ต้องใช้แอปเพิ่ม ใช้วิธีนี้เมื่อข้อมูลต้อง **ออกจาก** VRChat เท่านั้น เช่น leaderboard ข้าม instance หรือแผนที่บนเว็บ
:::

โลกเขียนหนึ่งบรรทัดลง log ของ VRChat จากนั้น `openworld-link` บน PC ของผู้เล่นอ่านแล้ว POST ไปยังเซิร์ฟเวอร์ของคุณ

1. **เซิร์ฟเวอร์:** ใส่ข้อความลับแบบสุ่มยาว ๆ ใน `keys/<world>.txt` แล้วรัน `openworld-host --keys keys --data data` หลัง HTTPS
2. **โลก:** ใส่ **OpenWorldLink** บน GameObject แล้วตั้ง **Server Url** (ลงท้ายด้วย `/`), **World Name** (ชื่อไฟล์ key ห้ามมีจุด) และ **Key** (ข้อความลับเดียวกัน)
3. **ผู้เล่น:** เปิด `openworld-link` ระหว่างเล่น และตอบ `y` เมื่อโปรแกรมถามเรื่องเซิร์ฟเวอร์ของคุณ

```csharp
public OpenWorldLink link;

public void _SubmitScore(int score)
{
    link._Send("score", "{\"score\":" + score + "}");
}
```

ข้อความแต่ละอันควรเล็กกว่าประมาณ 1 KB และ `type` เป็นคำสั้นหนึ่งคำที่ไม่มีช่องว่าง

### ความปลอดภัย

key ติดไปกับโลก และโลกสามารถถูก decompile ได้ ลายเซ็นของข้อความกันได้แค่การแก้ log หรือคัดลอกแบบง่าย ๆ **ไม่** กันคนที่ตั้งใจโกง จึงต้องตรวจทุกค่าที่เซิร์ฟเวอร์

### สิ่งที่โปรแกรมฝั่งผู้เล่นส่ง

โปรแกรมอ่านเฉพาะบรรทัดข้อความของ OpenWorld กับบรรทัด sign-in ของ VRChat เพื่อเอา id `usr_` ของผู้เล่น และไม่ส่งอย่างอื่นจาก log โปรแกรมขอความยินยอมครั้งเดียวต่อเซิร์ฟเวอร์ใหม่ บังคับใช้ HTTPS ยกเว้นการทดสอบบน localhost ถ้าเซิร์ฟเวอร์ออฟไลน์จะเก็บคิวไว้สูงสุด 1 MB แล้วลองใหม่

ใช้ได้บน **Windows เท่านั้น** ผู้เล่น Quest และมือถืออื่นส่งข้อความไม่ได้

### สิ่งที่เซิร์ฟเวอร์เก็บ

เซิร์ฟเวอร์ตรวจลายเซ็นและเลขลำดับของแต่ละบรรทัด แล้วต่อท้ายใน `data/<world>/<date>.jsonl` โดยใช้วันที่แบบ UTC โค้ดของคุณอ่านไฟล์เหล่านี้เอง

| ข้อจำกัด | ค่า |
|---|---|
| ขนาดต่อบรรทัด | 2 KB |
| จำนวนบรรทัดต่อ request | 500 |
| ขนาด body ของ request | 256 KB |
| request ต่อ IP | 10 ครั้งต่อวินาที |

ตัวกันการส่งซ้ำเก็บในหน่วยความจำ หลัง restart เซิร์ฟเวอร์จึงยอมรับบรรทัดเก่าได้หนึ่งครั้ง การส่งข้อมูล **กลับ** ไปหาผู้เล่นรายคนยังไม่ได้ทำ
